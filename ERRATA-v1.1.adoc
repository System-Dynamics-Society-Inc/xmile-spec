= Errata: XMILE Version 1.1
:toc:
:sectnums:

Version 1.1 withdrew seven subsections but did not update the text that referred
to them. This file records what is inconsistent in the specification as tagged
`v1.1`. Nothing here has been corrected in that tag: it reproduces the approved
document. The corrections are a separate editorial decision for the TC.

[IMPORTANT]
====
Every item below has a proposed fix on the `errata/v1.1-fixes` branch, as four
commits each scoped to one withdrawn feature, so any of them can be reviewed or
dropped on its own. They are proposed, not approved: see <<sec-what-was-done>>.
====

== How this happened

In the Word original a reference such as "Section 6.4.2" was ordinary typed
text, not a field. Nothing linked it to the section it named, so deleting a
section left its inbound references pointing nowhere, and deleting a section
renumbered its siblings so that surviving references silently changed meaning.
Neither failure produced any warning.

Both classes are now caught automatically: references are real cross-references
that Asciidoctor validates, and `tools/lint.py` rejects a reference typed as
literal text. See the README.

== References that now point at different content

Removing a section renumbered the ones after it, so thirteen references still
resolve but no longer name what the author meant. These are more dangerous than
the broken ones: they read as correct.

[cols="3,2,2",options="header"]
|===
| Reference as written | Meant in 1.0 | Now resolves to in 1.1

| Section 6.4.2 (×3) | Lamps and Gauges | Graphs
| Section 6.4.3 (×2) | Graphs | Tables
| Section 6.3.1 (×3) | Sliders and Knobs | Sliders (knobs no longer defined)
| Section 3.7.1.1 | Array Operations | Sub Ranges
| Section 3.7.1.2 | Array Slicing | Array Operations
| Section 3.7.1.3 (×3) | Array Built-in Functions | Array Slicing
|===

The array shifts are caused by the new Sub Ranges subsection, which was
inserted ahead of the existing array subsections.

== Feature flags still advertising withdrawn features

The XMILE Options section continues to define capability flags for features the
specification no longer describes:

* `lamp="…"` and `gauge="…"` on `<uses_outputs>`
* `<uses_inputs>` is documented as implying "sliders, knobs, switches, and
  option groups"
* `<uses_annotation>` is documented as implying "text boxes, graphics frames,
  and buttons"
* Section 6.3.1 still ends with "Descriptions of all other display attributes of
  a slider or knob can be found in Section 6.1"

== What was done

For each withdrawn feature the choice was between completing the removal and
restoring the section. The removals were deliberate, so the fixes complete them:
the conformance clauses and capability flags for withdrawn features are gone,
and the references that had drifted now point at the section they describe.

One case did not fit that rule. Chapter 4 requires `<image>`, `<video>`,
`<sound>` and `<link>` for event poster messages, and those tags were defined
only inside Graphics Frames and Buttons. Version 1.1 did not touch chapter 4, so
removing the messages would go further than the TC evidently intended. Those
four definitions were therefore moved into a new subsection under Annotations,
carried over as written apart from wording that named buttons. The
`<graphics_frame>` and `<button>` container tags remain withdrawn.

The four commits on `errata/v1.1-fixes`:

[cols="2,3",options="header"]
|===
| Commit | Effect

| Complete the withdrawal of the optional input devices
| Drops the conformance clauses for knobs, switches, option groups, numeric
  inputs, list inputs and graphical inputs, and the `<uses_inputs>` attributes
  that selected them.

| Complete the withdrawal of lamps and gauges
| Drops the lamp, gauge and zone clauses and the `lamp=` / `gauge=` flags.

| Correct the graph and table conformance cross-references
| Repoints the four clauses whose section numbers had drifted.

| Complete the withdrawal of graphics frames and buttons
| Drops the `<graphics_frame>`, `<button>` and `<menu_action>` clauses; moves
  the four message tag definitions to a new subsection. The only fix that adds
  text.
|===

Afterwards nothing in the specification refers to a withdrawn feature, no
reference is written as a literal section number, and the build resolves every
cross-reference.

== Open questions for the TC

. Was removing the input devices, lamps, gauges, graphics frames and buttons
  meant to be this thorough? Completing it drops conformance requirements that
  implementations may currently claim.
. Should event posters keep their image, video, sound and link messages? The
  fix assumes yes. If not, drop the fourth commit and remove the four bullets
  in Interactivity in Event Posters instead.
. `<uses_inputs>` and `<uses_annotation>` now each imply a single object type
  (sliders, text boxes). Whether they still earn their place is a design
  question rather than an erratum.
